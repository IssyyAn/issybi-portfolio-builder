# Dashboard design reference practice

Use this reference only for dashboard design. These are inspiration sources, not mandatory templates or assets to redistribute. Inspect current pages when tools permit and record access limits.

## Source set

- [Tableau Dashboard Showcase](https://www.tableau.com/data-insights/dashboard-showcase): Super Sample Superstore for compact analytical summaries and supporting trends; Profitability and Shipping KPIs for a primary plot paired with exception/detail views. ## Inspect and translate

For each accessible example, note specific traits: report canvas and margins; grid proportions; density; title/body/value typography; chart labels and axes; colour meaning; filters; detail table; component states. State which traits will be adapted and which do not fit the brief. No fabricated measurements or usability claims.

Choose one dominant direction, for example a compact analytical report with a wide trend and a narrower comparison view. Define a small coherent token set for type, spacing, colour, border and radius. Preserve clear synthetic-data status without making a warning banner the dominant design element.

## Acceptance

The important chart should have visual priority. Controls should be grouped and aligned. Numeric values should align and use consistent units. Selected filters and keyboard focus should be visible. Axis labels and chart titles should remain readable at the intended viewport. Table details should support the chart rather than overwhelm the opening view. Avoid arbitrary decorative elements and fabricated KPI deltas.

Link the actual reference pages in handoff notes. Describe observations and adaptations honestly; inspiration is not endorsement or affiliation. If tool access blocks visual inspection, label the visual review pending.
